# Codex 错误状态识别复盘（2026-09-11）

## 完成标准

- 普通容量警告、远程压缩失败应进入已有的失败处理流程，结束 Working（处理中）计时。
- 后台终端仍在运行，不影响判断当前代理轮次已经失败。
- 历史重绘、正常重连、普通警告、额度重置提示不能冒充当前轮次失败。
- 同一轮错误只处理一次；发送新一轮“继续”后，同类新错误仍能处理。

## 本次确认的问题

1. 第一张图的 `⚠` 紧贴容量错误文字，原先三处终态标记判断均要求符号后存在空白。错误候选能命中关键词，但稳定屏幕确认拒绝它，计时继续显示 Working。
2. 第二张图在错误和输入框之间还有 `1 background terminal running · /ps to view · /stop to close`。原先只允许空白，因此最终失败同样被拒绝。
3. `Error running remote compact task:` 是 Codex 的错误包装前缀，原先的整行终态规则未覆盖。它会影响旧运行状态的清理；对于 503、断流等内层错误，还会影响终态与重连的区分。
4. 字节扫描、旧运行状态清理、稳定屏幕确认分别维护标记判断，容易出现只修一处、其他入口继续漏判的问题。

只读检查了实际运行包：其中已包含 `57986ff`、`83a8544` 引入的规则，不能将本次问题归因于尚未更新到上一次修复。

## 修复范围

- `codex-cli-error-classifier.ts`：共用整行终态判断，兼容符号后无空格及 Unicode 变体选择符；只解开已确认的远程压缩错误前缀。
- `codex-error-replay-guard.ts`：复用同一判断，只允许一条格式完整的后台终端状态栏夹在错误与输入框之间。
- 黄色警告仍只接受容量或服务过载终态；MCP 启动警告等不能因为包含错误关键词就被确认成失败。
- 继续使用现有失败计时、通知、按设置自动继续的调用链，不增加另一套状态机。
