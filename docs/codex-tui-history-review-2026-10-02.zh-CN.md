# 新版 Codex 历史浏览误报与滚动按钮复盘

## 完成标准

- 浏览旧会话时，历史错误不触发失败通知或自动继续。
- 返回最新消息后，本轮真实错误仍能确认，同轮不重复处理。
- 终端顶部／底部按钮支持新版自管历史，保留旧版普通滚动行为。

## 历史经验

先复查 `08f2954`、`5fc5f01`、`7d58915`、`e3d1e9f`、`5770008`、`fb81594`，以及 [9 月 28 日复盘](./codex-error-status-review-2026-09-28.zh-CN.md)。

- 输出字节不等于当前屏幕；局部重画可能只有旧错误正文。
- 输入框不能证明本轮结束；最终失败需要核对稳定屏幕。
- 时间保护、同类文字去重都不能单独解决历史回放，且不能吞掉新轮次真实错误。
- 保留已有轮次、重连、缩放、容量警告和后台终端栏处理。

## 本次根因

只读对照 Codex 源码的 `tui/src/app/owned_transcript.rs`、`tui/src/tui/alternate_screen.rs` 和 `tui/src/transcript_view/`：

- 新版默认由 Codex 接管备用屏幕，并接收鼠标事件来滚动自己的历史视图。滚轮重画不必发送旧防护识别的清空滚动区命令。
- 历史视图仍保留输入框；`esc latest` 等浏览提示可能出现在输入框下方。旧屏幕确认只核对错误与输入框之间的内容，会漏掉这些提示。
- CodexFlow 的上下滚动按钮只调用 xterm 缓冲区端点滚动。备用缓冲区没有普通滚动历史，因此按钮无效。
- 新版 `JumpTarget::from_key` 支持 Ctrl + Home／End，分别跳到会话开头和最新消息。

## 修复

- 用共享的屏幕识别函数检查输入框附近的返回底部、历史导航、搜索和选区提示。稳定历史画面清除旧错误候选，不记为已处理的新错误。
- 错误确认和完成计时共用浏览状态检查，避免旧完成标记结束正在运行的新任务。
- 滚动按钮仅在 Codex 标签、备用缓冲区、已启用鼠标报告且有输入框时发送 Ctrl + Home／End；其它情况继续使用原有滚动。
- 依据实际终端模式适配，不按版本号分支；禁用备用屏幕时仍走普通缓冲区逻辑。

- 最终文件固定后重新执行全量测试：243 个文件、1682 项全部通过，包含前端类型检查。
