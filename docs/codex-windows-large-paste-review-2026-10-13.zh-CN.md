# Windows Codex 大文本发送卡住复盘

## 原因与历史经验

现场文本约 19.7 万个 UTF-16 字符，包含 579 行。输入框发送停在开头；Codex 原生右键粘贴立即显示完整字符数占位符。

Codex 的 Windows 后端读取控制台按键记录。输入框原来将整段正文写进 ConPTY，并将正文换行转成 Alt+Enter；大文本仍会退化成大量按键事件。原生右键粘贴则从剪贴板一次读取正文，直接生成整段粘贴事件。

已复查 CodexFlow 的 `ea3eec1`、`ef80006`、`533aaa0`、`25490b8`，以及仓库已有的 Windows 换行调查和长提示词渲染复盘。此前修复分别保护多行正文、真实回显、回车时序和错误历史过滤。直接改回终端组件的普通粘贴会重现第一行提前提交；增加固定等待也不能消除逐键处理。

只读参考的 Codex 源码为 `a9b0815167`。该提交新增键盘文本粘贴，但本机实际运行的 0.162.1 尚不支持 Ctrl+V 文本回退。验证采用已存在且实测可用的原生右键入口，不按版本号猜测能力。

## 修复

- Windows Codex 超过 4096 字符的输入复用原生整段粘贴，发送和仅写入共用同一实现。
- 根据真实终端鼠标报告模式，在输入光标处写入右键事件；不移动系统鼠标。
- 临时借用剪贴板并恢复文本、富文本和图片。遇到不能恢复的格式时保持原剪贴板不动；并发请求互斥，期间用户新复制的内容不被覆盖。渲染进程失联时十秒内自动释放。
- 等待本轮完整字符数占位符稳定显示、终端写入完成后才补一次提交。四秒仍未确认就结束本次发送，不用正文尾部、固定超时回车或逐键重发来兜底。
- 发送失败保留输入框内容并取消计时；等待期间重复点击不重复发送，成功后不清除用户刚输入的新草稿。

原有短文本换行编码、WSL 和其它引擎的发送路径继续使用原策略。完成检测及错误重画保护无需调整。

## 验证范围

使用独立 Codex 配置、临时工作目录和本机 HTTP 模拟服务，不连接用户现有会话或真实模型。原始文件只通过诊断参数读取，不进入测试夹具。

原实现的大文本发送没有形成完整请求；终端组件普通粘贴提前提交第一行。修改后的实际 TerminalManager、TerminalAdapter、真实 xterm、生产剪贴板管理器及 Codex 0.162.1 联测，自动提交约 0.6 秒，规范化换行后的 196276 字符正文逐字一致，只提交一次。仅写入模式同样完整，在独立提交键之前没有请求；系统剪贴板已恢复。

回归用例使用通用数据，覆盖三种 Windows 终端、空行、缩进、表情、尾部换行、缺少入口、超时、剪贴板变化、终端切换、并发点击、草稿保留以及真实终端模式检测。应用发送入口测试直接提取生产函数，验证失败不会走旧兜底或触发自动提交。

工程检查全部通过：251 个测试文件、1895 项测试，最终前端类型检查、主进程和前端构建、多语言检查及差异空白检查。测试结束后已恢复 Electron 原生依赖。

已生成 `dist/win-unpacked/CodexFlow.exe`。包内主进程、预加载、新粘贴管理器、页面入口和主前端文件与最终构建逐字节一致。新包在 Electron 29.4.6、原生模块接口版本 121 下完成 SQLite 内存查询及终端模块加载核验。

需要使用同时包含新主进程、预加载和前端的新构建；仅刷新旧程序的前端不足以启用本次修复。
