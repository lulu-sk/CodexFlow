## 已修复

### Codex

- 使用官方 `account/read`（账号读取）与 `account/rateLimits/read`（额度读取），只有旧版明确不支持时才使用历史接口。
- 邮箱、套餐与登录类型以官方账号结果为准，令牌只补充身份 ID。API Key 或没有邮箱的已登录账号不会被误显示为退出登录。
- 修复直接安装的 Windows 可执行文件查找，兼容新版 npm 平台包；WSL 使用所选发行版中的 Codex，仍支持显式指定程序路径。
- 查询环境优先使用 Codex 自己的独立设置，与其它引擎保持一致；环境切换时重建对应的后台进程。
- 完成初始化握手，为初始化、业务请求和历史 HTTP 请求补上超时；进程退出后结束等待并清理计时器。
- 检测认证文件变化，空闲查询进程重新启动，从而读到外部终端的登录、退出和切换结果；正在进行的查询按原身份完成。
- 额度窗口正确转换分钟/秒，保存绝对重置时间，避免缓存画面每次渲染都把重置时间向后推。缺失窗口不再显示“无限制”。
- 备份定位遵守 `CODEX_HOME`，支持默认 WSL 发行版；去重签名包含用户和工作区，避免同一用户的不同工作区互相覆盖。
- 备份、列表、恢复、删除和非法路径拦截已在临时目录验证，没有覆盖真实账号凭据。旧版备份继续可用，新签名可能产生一份新的记录。

### Claude

- 新增官方 OAuth 用量接口，Windows 无需依赖第三方缓存；保留同凭据的短时内存缓存和 WSL 终端抓取兜底。
- 缺失、空字符串和 `null` 百分比保持未知，不能转换成 0%。
- 无法绑定账号的 ccline 磁盘缓存不再认领为当前账号额度；只复用本进程同一凭据五分钟内的成功查询。切换、退出、过期和认证拒绝不能被缓存掩盖。
- 五小时、周与 Opus 窗口各自使用自己的重置时间，不再将五小时缓存重置时间套给周窗口。
- 兼容 `CLAUDE_CONFIG_DIR` 和 UTF-8 BOM；终端抓取退出时保留其结构化错误提示。

### Gemini

- 支持 `GEMINI_CLI_HOME`，并读取当前 WSL 环境自己的项目变量。
- 从已安装官方 CLI 只读提取 OAuth 客户端配置，用于刷新过期凭据；源码未写入客户端凭据常量。WSL 缺少 Node 时，可复用 Windows 官方安装包的客户端配置，登录凭据仍从 WSL 读取。
- 接口返回 401 时只刷新并重试一次；其他失败不重复请求。
- 付费套餐优先于基础套餐；免费套餐初始化不提交用户项目，未结束的初始化不能被当作成功。
- 遵守官方默认套餐选择规则；账号需要验证或没有服务资格时明确报错，不再误报为无法识别套餐。

### Grok

- 官方 `/billing?format=credits` 接口及新旧额度字段仍匹配当前源码。
- 兼容套餐的蛇形字段，异常金额保留未知；只有 proto3 明确省略的金额值才视为 0。
- Windows 支持 `GROK_AUTH_PATH`；401/403 不再回退旧日志来掩盖登录失效。

## 本机真实查询结果

| 环境 / 引擎 | 实际结果 |
| --- | --- |
| Windows / Codex | 后台进程与官方协议握手成功，返回未登录；额度接口正确拒绝未登录查询 |
| Windows / Claude | 现有 OAuth 凭据过期，且没有可用刷新令牌；旧缓存未作为当前额度使用 |
| Windows / Gemini | 成功读取官方安装包的客户端配置，但 Google 刷新接口返回 HTTP 400、`invalid_grant`；需要重新登录 |
| Windows / Grok | 当前环境未发现有效官方 OAuth 登录 |
| WSL / Gemini | 补齐真实安装版本的客户端标识后复测，令牌刷新、加载账号和初始化接口均返回 HTTP 200；服务仍未返回可用项目，并提示当前客户端不再支持个人版、建议迁移至 Antigravity；尚未取得额度 |
| WSL / Grok | 当前环境未发现有效官方 OAuth 登录 |
| WSL / Claude | 二审修复抓取脚本后复测，Claude 终端界面未在 10 秒内启动，尚未取得额度 |
| WSL / Codex | 默认发行版的登录 shell 中没有找到可用 Codex 命令，未执行账号/额度查询 |

默认 WSL 环境缺少 Node；查询代码的客户端配置兜底已补齐，但命令行程序本身的安装与登录仍需在实际使用的环境完成。

本次未进行真实账号切换、交互登录或界面端到端验收。Codex 文件备份适用于 `auth.json`，不负责导出系统凭据库；Gemini 加密凭据库、ADC、API Key/Vertex 计费不是本次文件 OAuth 查询的验证范围。Grok 的 API Key 与团队订阅继续返回原有“不支持此额度查询”的状态。

## 第二轮复审补充

- Codex：固定查询开始时的运行环境，防止查询结束后把旧环境账号与新环境认证文件拼接；备份和恢复前核对文件实际身份；启用记录时，旧账号查询或备份失败即停止切换，保留原凭据。自动记录只合并最新设置，避免等待期间关闭记录后又被旧设置重新开启。补齐 macOS/Linux 的 PATH 命令查找。
- Gemini：只有官方明确要求验证的场景才提前停止，其他套餐不可用不再阻断仍可用套餐的初始化；固定首次操作名继续轮询，保留轮询 401 状态，并拒绝失败或未完成的初始化结果；兼容接口版本及较小的安装包代码块。依据官方请求补齐客户端标识，读取实际安装版本并保留 CodexFlow 查询身份；没有版本信息时不编造 CLI 版本。
- Claude/Grok：取消没有账号归属的历史磁盘缓存兜底，只保留按环境与凭据隔离的五分钟成功缓存。Grok WSL 从目标发行版读取认证路径、配置目录与代理地址，未指定发行版时遵守系统默认。
- Claude 终端脚本：修复首次循环被错误退出、缺失百分比变成零、重置文字被误当百分比而生成非法 JSON 三处问题。已通过 Bash 语法检查及模拟 tmux 的实际执行验证。
- 四引擎界面：环境切换、重复刷新后丢弃过期请求结果，兼容 React 开发严格模式；Codex 认证变化时清除所有环境的账号和额度缓存。顶部栏使用各引擎独立环境，与后端查询保持一致。

独立 Node 真实诊断复用了应用现有代理，仅替换 Electron 专用日志器，未模拟业务或网络结果。本机 Electron 运行文件缺失，因此没有进行图形界面验收。Claude/Grok 当前仍依赖官方 CLI 更新过期凭据，应用不自行刷新其过期令牌。

Gemini 的迁移提示是本机账号与当前客户端组合下的实际服务响应，不能据此推断所有账号或官方 CLI 都已停用。
