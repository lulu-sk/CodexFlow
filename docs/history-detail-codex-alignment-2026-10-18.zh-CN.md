## 关键边界

- 折叠依赖原始阶段、轮次和时间信息；没有可靠耗时则显示消息数，不伪造耗时。
- 正在执行的 `commentary` 不当作最终答复，启用推理筛选后推理内容也归入执行过程。
- 展开状态保存在详情层，虚拟列表卸载消息不会丢掉选择；搜索结束后恢复原选择。
- 单文件补丁从原始记录选择，保留重复修改段及跨文件操作顺序；部分撤销后，整轮撤销跳过已经撤销的文件。
- 撤销仍先校验当前文件，后续修改冲突时停止；无法识别的文件路径不执行单文件撤销。
- `apply_patch` 的相对路径按实际工作目录解析并校验仓库边界；标准 Git 统一差异维持仓库根目录语义。
- 撤销与重新应用同时检查工作目录、具体文件和最近存在父目录的真实位置，拒绝越界目录链接与无法解析的符号链接。
- 差异正文、项目或工作目录变化后清空文件撤销状态，进行中的旧响应不会覆盖新卡片。
- 文件行号和代码语言标题不参与正文搜索，避免展示标签抢占命中编号。
- 完全没有可靠轮次编号的旧日志保持独立记录，避免误合并不同用户轮次。

## 截图反馈后的修复

| 反馈 | 原因与处理 |
| --- | --- |
| 折叠后找不到展开入口 | 入口随最终答复上移，旧滚动位置仍指向后面的消息。切换前记录按钮位置，切换后校准普通或虚拟列表，保留键盘焦点；用户主动滚动时停止校准。 |
| 已编辑文件缺少悬停效果 | 高亮原先仅覆盖部分按钮。改为整行背景、边框及更多菜单统一响应悬停和键盘焦点。 |
| 历史详情加载变慢 | 正确归并用户轮次后，原有卡片定位会在每条消息后扫描整段历史。改为解析结束后一次整理，保留各轮最新卡片及显示顺序。普通 Markdown 正文同步显示，代码高亮插件使用稳定配置，避免界面更新重复解析。 |
| 图片路径有重复反斜杠 | 工具文本中的转义路径进入图片内容。后端解析和前端旧缓存共用纯路径整理函数，统一标题、说明、预览地址和复制结果，保留网络共享路径前缀。 |
| 网页链接仍为旧样式 | 上次仅强调本地文件链接。这次为 HTTP/HTTPS 网页链接补充强调色、外链图标及悬停、键盘焦点样式。 |

本地临时 JSONL（逐行记录文件）基准：200 个用户轮次、2 万条输出、4.16MB，修复前完整读取约 2319～2573 毫秒，修复后约 65～70 毫秒，缓存读取约 2.25～2.56 毫秒。实际调用 `readHistoryFile` 和记录流读取入口，使用去标识化生成数据；顺序检查通过且没有跳过记录。此计时不包含跨进程传输、前端渲染或 WSL（Linux 子系统）磁盘耗时，不能据此保证任意会话均在一秒内完整显示。

对截图对应真实会话的只读测量进一步发现：记录仍在增长，测量时约 270～272MB；修复前完整读取约 3785～3885 毫秒，修复后约 1076～1085 毫秒，缓存读取 0.17 毫秒。最后一次测量有 182 张图片，其中 179 张已经有本地预览，但完整备用图片数据仍随历史返回。历史返回现改用短图片引用，主进程保留原图，预览及复制按需读取；备用图片仅在主图失效时加载。

最终返回体由 269,734,531 字节降为 9,518,549 字节，减少 96.47%；转换耗时 2.73 毫秒，缓存转换 1.37 毫秒；JSON 序列化与 UTF-8 字节计量由 873 毫秒降为 59 毫秒。182 个短引用全部能取回对应原图，原始解析缓存保持完整。引用绑定图片快照，刷新不会错绑；有限引用表淘汰后重新打开历史可重新登记。本次没有新增跨进程通道。

本次不升级缓存格式，旧缓存图片在显示时直接修正，避免因展示调整触发全库重建。

本轮验证：36 个历史相关测试文件、280 项测试全部通过；图片按需传输及现有输入框、复制链路的补充验证为 6 个文件、47 项全部通过。随后补充快速换图错误事件回归，图片预览单文件 16 项全部通过。前端类型检查、前后端构建、翻译校验和差异检查通过，测试后已恢复 Electron 原生依赖。组件测试覆盖开发和打包两种协议环境；未进行实际窗口画面验收，上述速度不等同于页面首屏总耗时。

## 展开方向修正

原先耗时按钮始终位于最终答复前，恢复的过程消息出现在按钮上方。展开时现将按钮放在首条可见过程之前，收起时回到最终答复之前，保留消息原来的时间顺序。滚动定位随按钮的新位置更新，并在布局阶段立即校正，避免虚拟列表先跳到最终答复再调整。

回归覆盖按钮与过程内容的先后顺序、筛掉首条过程后的入口位置，以及普通和虚拟列表在非零滚动位置的展开、收起和再次展开。最终答复、文件变更及搜索的原有显示规则保持一致。通过 `npm run test` 验证 5 个相关测试文件、27 项测试及前端类型检查，翻译校验通过；测试后已恢复 Electron 原生依赖。

## 进一步优化详情读取

本轮分别测量记录读取、缓存出口和前端数据整理，优化已确认的耗时环节：

- 普通 Codex 记录按换行字节拆分，完整行到齐后只解码一次，减少内嵌图片长行的反复组装。继承前缀的逻辑历史继续使用原读取路径；默认读取块大小不变。
- 同时有本地预览地址和会话内完整图片时，Codex 解析阶段延后文件存在性检查。实际预览失败仍走原有备用图，复制仍尝试全部图片来源；没有备用数据的路径图片与其他提供方保持原检查方式。
- 后台摘要索引跳过仅用于详情显示的工具、推理、状态与未知记录正文构造，继续提取标题、工作目录、运行环境和会话关系。
- 前端复用默认类型筛选结果，并为虚拟列表提供稳定的取键函数，减少筛选或父层刷新时的重复计算。

稳定的真实记录快照为 275,073,630 字节、3500 条消息、186 张图片。每次清空解析缓存后交错测量，原实现四次为 1490/2608/1588/1596 毫秒，新实现为 979/956/1223/1110 毫秒，中位数从 1592 降为 1044 毫秒，约减少 34.4%。归一化图片主备来源位置及回退说明后，全部正文、消息顺序与 186 张会话内图片的数据指纹一致，没有跳过记录。

首次观察到的旧实现耗时 4066 毫秒，其中 186 次图片文件检查累计 2710 毫秒；新实现首次为 1019 毫秒，仅有 3 次检查、累计 0.39 毫秒。这是本机文件系统首次探测的观测值，不能将全部差额归因于读行算法，也不能保证其他磁盘或网络路径有相同加速。

后台摘要中仅显示正文的构造在独立测量中耗时约 331 毫秒，产生约 2.72 亿字符后被丢弃；本轮跳过该构造，不将它等同于完整索引任务的总耗时。缓存出口中位耗时约 0.262 毫秒，没有正文读盘或 JSON 重解析；前端数据整理为几十毫秒内，本轮没有改动图片配对或 Markdown 解析规则。

上述为隔离测量，不是 Electron 窗口从点击到首屏的总时间。巨型原始临时快照在测量结束后删除；本轮不改变缓存格式，不触发全库重建。

验证覆盖 36 个相关测试文件、316 项测试。首轮 314 项通过，两处测试预期分别需适配图片延后检查和真实文件的字节流模式；修正后通过 `npm run test` 复跑对应两文件，39 项全部通过。前端类型检查、前后端构建、翻译校验与差异检查通过，测试后已恢复 Electron 原生依赖。换行、多字节字符、超长行、读取上限、错误关闭、继承前缀、摘要元数据，以及开发和打包环境的图片回退均有覆盖。
